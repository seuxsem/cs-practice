# Различие Git и GitHub

**Git** — это распределённая система контроля версий. Она отслеживает изменения в файлах вашего проекта, сохраняет их в виде снимков (коммитов) и позволяет откатываться к предыдущим версиям. Git работает локально: хранит всю историю изменений на вашем компьютере и даёт полный контроль над проектом. 

**GitHub** — это веб-сервис, который работает поверх **Git**. Он предоставляет облачное хранилище для Git-репозиториев, упрощает совместную работу в команде, позволяет создавать ветки, делать код-ревью через Pull Request и управлять задачами. GitHub не заменяет Git, а дополняет его, добавляя инструменты для командной работы. 

**Ключевое различие:** Git — это движок для работы с версиями, а GitHub — это платформа, которая делает эту работу удобнее для команды. 

# Использование команды:

**git status** — показывает текущее состояние репозитория. Выводит три секции:
    *   `Changes to be committed` — файлы, которые уже добавлены в индекс и готовы к коммиту;
    *   `Changes not staged for commit` — файлы, изменённые, но ещё не добавленные в индекс;
    *   `Untracked files` — новые файлы, о которых Git пока не знает.

**git diff** — демонстрирует разницу между рабочим каталогом (текущими редактируемыми файлами) и индексом (промежуточной зоной подготовленных изменений). То есть показывает, что именно изменилось, но ещё не подготовлено к коммиту.

**git diff --staged** — сравнивает содержимое индекса (подготовленные изменения, добавленные через **git add**) с последним коммитом. Показывает, какие именно правки войдут в следующий коммит.
