# Отличия команд Git и поиск изменений

## 1. Отличия git diff, git show и git log

| Команда | Что показывает? | Основное назначение |
| :--- | :--- | :--- |
| **`git diff`** | Разницу между состояниями (между рабочим каталогом, индексом, коммитами или ветками). | Посмотреть незакоммиченные изменения или сравнить две разные точки в истории. |
| **`git show`** | Детальную информацию о конкретном объекте Git (чаще всего о конкретном коммите). | Посмотреть автора, дату, описание и полный патч (diff) одного конкретного коммита. |
| **`git log`** | Историю коммитов (список ревизий с их метаданными). | Проверить хронологию разработки, найти нужный коммит по автору, дате или сообщению. |

---

## 2. Что именно нашли команды log -S и blame?

* **`git log -S "строка"`** *(Pickaxe search)*:
  Ищет коммиты, в которых количество упоминаний заданной строки **изменилось** (строка была добавлена или полностью удалена). Она помогла найти точный момент в истории (коммит), когда в коде появилось или исчезло интересующее нас ключевое слово или функция.
  
* **`git blame`**:
  Показывает автора, хэш коммита и дату последнего изменения для **каждой отдельной строки** в указанном файле. Она помогла определить, кто именно и когда последним редактировал конкретную строчку кода, вызвавшую ошибку.

 # Отличия `git restore` и `git restore --source`

*   **`git restore <file>`**
    *   **Откуда берутся файлы:** По умолчанию из индекса (Staging Area). Если файла в индексе нет — из последнего коммита (`HEAD`).
    *   **Что произойдет с вашими правками:** Текущие незакоммиченные изменения в рабочей директории будут **полностью удалены** и заменены версией из индекса/HEAD.

*   **`git restore --source=<commit_hash/branch> <file>`**
    *   **Откуда берутся файлы:** Из конкретного указанного источника (коммита, ветки, тега).
    *   **Что произойдет с вашими правками:** Изменения в рабочей директории будут **перезаписаны** состоянием файла на момент выбранного коммита. Локальный индекс (Staging Area) при этом по умолчанию не пострадает.

    # Отличия git revert от git reset --hard

Команда **`git reset --hard`** перемещает указатель ветки назад и стирает коммиты из истории, а также удаляет все изменения в рабочей директории. В то же время **`git revert`** создает новый коммит, который отменяет действия предыдущего, оставляя всю прошлую историю нетронутой.

## Главные отличия

| Критерий | `git reset --hard <commit>` | `git revert <commit>` |
| :--- | :--- | :--- |
| **Принцип работы** | Перемещает указатель ветки назад на указанный коммит | Создает новый коммит, инвертирующий изменения |
| **История коммитов** | Переписывает и удаляет коммиты из истории | Сохраняет всю историю, добавляя новый шаг |
| **Локальные изменения** | Безвозвратно стирает все незакоммиченные файлы | Безопасен для рабочей директории |
| **Применение** | Только для локальной (не опубликованной) истории | Для любой истории, особенно публичной |
| **Требует `--force` push**| Да, если коммиты уже были отправлены на сервер | Нет, это стандартный коммит добавления |

---

## Почему в опубликованной истории безопаснее использовать revert

* **Защита от расхождения веток:** Если вы уже отправили (`git push`) коммиты в общий репозиторий, их могли скачать другие разработчики. Использование `git reset --hard` заставит вас делать `git push --force`. Это сломает историю у коллег и приведет к сложным конфликтам при слиянии.
* **Сохранение контекста:** В командной разработке важно понимать, почему код изменился. С `git revert` в логе остается прозрачная запись об отмене конкретного решения, что помогает избежать повторения ошибок.
* **Предсказуемость:** `revert` — это безопасная операция добавления кода. Она никогда не приводит к потере данных у команды и не требует деструктивных действий с общим репозиторием.

# Отличие тега от ветки в Git

* **Тег (Tag)** — это **постоянный указатель** на конкретный коммит («снимок» состояния кода). Он статичен и не перемещается при создании новых коммитов. Используется для фиксации версий и релизов.
* **Ветка (Branch)** — это **подвижный указатель**, который автоматически перемещается вперед при добавлении каждого нового коммита. Используется для активной разработки.

**Главное отличие:** Ветка растет и меняется вместе с разработкой, а тег всегда указывает на один и тот же момент в истории.
